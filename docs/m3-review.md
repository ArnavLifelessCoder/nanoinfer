# M3 review packet

Review `git diff main...m3`. The base is approved M2 commit `e349784`, now on
remote `main`. M3 is isolated on `m3`; merging it into `main` awaits approval.

## What was built

Preallocated per-layer K/V storage, scalar cached prefill and single-token decode,
greedy/temperature/top-k/top-p sampling with a seeded RNG, the `gpt2rt` CLI, and
a tiktoken wrapper. The existing full-prefix reference remains unchanged.
The [runtime contract](runtime.md) specifies cache state, absolute positions,
sampling order, errors and reproducibility.

| Acceptance criterion | Evidence | Status |
|---|---|---|
| Cached logits equal full recomputation at every position | Exact finite float equality for all vocabulary entries at 101 pretrained and 102 tiny-model prompt/decode positions per preset; additional random full-context tests | Met |
| Decode uses prompt length plus step | Full-context tests from prefill lengths 1, 7, 31, 63 and 64; every generated position, including the final emitted token, checked against full recomputation | Met |
| Seeded sampling reproduces output | Sampler and CLI replay tests; distinct seeds produce distinct sampled sequences; top-k/top-p support and temperature checks | Met |
| Golden correctness remains intact | Every prompt logit and complete block/final-LN state passes the approved PyTorch bounds; all three continuations match 32/32 tokens | Met |
| Tests in CI | Four Windows/Linux Debug/ASan jobs and lint pass; cached golden, CLI and full-context tests are registered with CTest | Met |

The [summary](../results/m3-summary.json) is generated by
`scripts/summarize_m3.py` from the saved reports. Debug and ASan summaries are
identical. Maximum pretrained PyTorch logit error is `0.00018310546875`;
maximum hidden elementwise error/bound ratio is `0.943782678711196`.
Cache/reference logit and hidden differences are exactly zero.

The approved hidden bound remains `1e-4 + 1e-6 * abs(torch)`. The separate
strict small-value hidden gate remains withdrawn. M4 must compare optimized
forward results against both the scalar reference and PyTorch.

## Full local validation output

Debug and MSVC ASan each pass **11/11 CTest cases**, **42/42 pytest cases**,
and **29 unit tests plus 2 full-context cache tests** with both seeds 42 and 1234.
Both builds are warning-free. The complete outputs are linked below.

Earlier local ASan attempts intermittently stalled in native subprocesses in
the loader/schema/reference harnesses without a sanitizer diagnostic. A separate
regression reproduced how inherited output handles can delay pipe capture after
the parent exits: [before](../results/m3-capture-regression-before.txt),
[after](../results/m3-capture-regression-after.txt). The correctness harness now
captures to temporary files and enforces a native-process timeout. Nonzero exits,
stderr and timeouts remain failures.

That capture change did not eliminate every local timeout: a subsequent full
ASan run [timed out in model_schema](../results/m3-asan-timeout.txt), while the
[isolated schema rerun](../results/m3-asan-schema-recheck.txt) passed. A subsequent
[attempt](../results/m3-asan-isolated-attempt.txt) reported empty JSON output in
`generation_cli` and timed out in `golden_tiny`. The latter
[passed when rerun with file redirection](../results/m3-asan-golden-recheck.txt).
The cause of these intermittent local process/output failures is unconfirmed.
The final passing ASan validation uses a fresh `build/asan-m3` directory, sequential CTest
execution with output redirected directly to a file, a 180-second CTest limit
and the unchanged 60-second native subprocess limit. No runtime, numerical or
sanitizer settings were changed in response.

## Reproduce

```powershell
.\scripts\test-m3.ps1 -Preset debug -Pretrained
.\scripts\test-m3.ps1 -Preset asan -Pretrained
.venv\Scripts\python.exe scripts/summarize_m3.py
```

The final local ASan suite used the same preset in a fresh build directory,
reusing the already fetched, pinned GoogleTest source:

```powershell
. .\scripts\dev-shell.ps1
cmake --preset asan -B build/asan-m3 "-DFETCHCONTENT_SOURCE_DIR_GOOGLETEST=$PWD/build/debug/_deps/googletest-src"
cmake --build build/asan-m3
ctest --test-dir build/asan-m3 -j 1 --timeout 180 --verbose --no-tests=error *> build/m3-asan-file-tests.txt
```

The pretrained checks require the ignored `models/gpt2.bin` exported from the
pinned GPT-2 revision in `golden/manifest.json`. The scripts preserve M2 evidence
and save M3 output separately. Linux uses the same CMake presets and CTest suite;
run `python -m tests.golden_cached` with the executable/model/golden/directory/
report arguments shown in CMake or the PowerShell script.
